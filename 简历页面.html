设计模式 · 扩展性

签约框架重构:5 种合同类型统一管控

问题 · 每新增一种合同类型需改 3-5 处代码,开发周期 3-5 天

方案 · 策略模式抽象 ContractInvoker + 模板方法封装 CreateContractHandler 标准流程 + 泛型上下文容器自动装配

5 天 → 1 天 · 代码量 -40%
点击展开详细设计 ↓ 
public abstract class CreateContractHandler implements ContractInvoker {
    public final ContractResult invoke(CreateContractContext ctx) {
        idempotentCheck(ctx);       // 幂等校验(所有合同共用)
        validateParams(ctx);         // 参数验证(所有合同共用)
        Contract c = doCreate(ctx);  // 合同创建(子类实现)
        afterCreate(c, ctx);         // 后置回调(所有合同共用)
        return ContractResult.success(c);
    }
    protected abstract Contract doCreate(CreateContractContext ctx);
}

核心:execute 用 final 锁死防止子类破坏流程,doCreate 让子类实现个性化创建逻辑。 CreateContractContext 是泛型 Map 容器,个人装 8 项(身份/银行卡/人脸),机构装 15 项(企业资质/对公账户)。

性能优化 · 必讲亮点

N+1 查询优化:HashMap 方法内缓存

问题 · 结算列表 200 条记录循环调用户 RPC,最差 200 次调用,接口 3-5 秒

方案 · 导出一周操作日志发现 operatorId 重复度 85%+,方法内 HashMap + computeIfAbsent 做请求级缓存

3-5 秒 → 500ms · RPC -90%
点击展开详细设计 ↓ 
Map<Long, UserDTO> userCache = new HashMap<>();
return list.stream().map(s -> {
    UserDTO operator = userCache.computeIfAbsent(
        s.getOperatorId(),
        uid -> userService.getByUserId(uid)   // 只执行一次
    );
    vo.setOperatorName(operator.getName());
    return vo;
}).collect(toList());

关键点:HashMap 是方法内局部变量,不跨线程不用 ConcurrentHashMap。 computeIfAbsent 同 key 只执行一次 lambda,第二次开始从 Map 取。 生产监控命中率稳定 85%+。

架构 · 新旧系统兼容

organization_mapping 新旧 ID 双向转换

问题 · 老分润系统(千万级数据,几十个业务线在用)改不动,新机构主数据系统不能被污染

方案 · 独立映射表 + Service 层统一翻译,前端用新 ID,调分润系统自动翻译老 ID,返回再翻译回新 ID

千级机构平滑过渡 · 零侵入新业务
点击展开详细设计 ↓ 
CREATE TABLE organization_mapping (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    org_id VARCHAR(64) NOT NULL,
    old_system_id VARCHAR(64) NOT NULL,
    status TINYINT DEFAULT 1,
    UNIQUE KEY uk_org_id (org_id),
    UNIQUE KEY uk_old_system_id (old_system_id)
);

核心字段只要 3 个:新 ID、老 ID、status。两边都加唯一索引,双向查询 O(1)。 Service 层提供单次 + 批量两个接口,批量走 IN 查询减少 DB 调用。

架构思维 · 反直觉

过期状态动态计算:消除定时任务依赖

问题 · 合同过期状态靠定时任务扫表更新,延迟最长 1 小时,Job 挂了状态永远错

方案 · 数据库只存 2 种基础状态(已生效/已终止),"已过期"用 SQL CASE WHEN 实时计算

1 小时延迟 → 实时 · 消除定时任务
点击展开详细设计 ↓ 
SELECT id, contract_number,
       CASE
           WHEN status = 1 AND cooperation_end_time < NOW() THEN 2
           WHEN status = 1 THEN 1
           WHEN status = 9 THEN 9
       END AS status_view
FROM contract;

设计原则:事实存库(已生效、已终止 — 有发生时间点),推导值动态算(已过期 — 时间到自动变)。 组合索引 (status, cooperation_end_time) 走最左前缀。 未来加"临期"状态同样 CASE WHEN,不改表不加 Job。
