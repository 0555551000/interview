💡 方案:策略 + 模板方法 + 泛型上下文

策略接口(ContractInvoker)

public interface ContractInvoker {
    ContractType getType();
    ContractResult invoke(CreateContractContext ctx);
}

模板方法基类(CreateContractHandler)

public abstract class CreateContractHandler
        implements ContractInvoker {

    public final ContractResult invoke(CreateContractContext ctx) {
        idempotentCheck(ctx);       // 共性:幂等
        validateParams(ctx);        // 共性:参数校验
        Contract c = doCreate(ctx); // 个性:子类实现
        afterCreate(c, ctx);         // 共性:后置回调
        return ContractResult.success(c);
    }

    protected abstract Contract doCreate(CreateContractContext ctx);
}

泛型上下文(CreateContractContext) — 个人装 8 项,机构装 15 项

public class CreateContractContext {
    private final Map<ContextKey, Object> data = new HashMap<>();

    public <T> T get(ContextKey key, Class<T> type) {
        return type.cast(data.get(key));
    }

    public static CreateContractContext forPersonal(Long guid) {
        // 装实名、银行卡、人脸识别... 8 项
    }

    public static CreateContractContext forOrg(String orgId) {
        // 装企业资质、对公账户、法人身份证... 15 项
    }

🎤 面试高频追问

Q: 策略+模板方法一起用,会不会过度设计?

两个模式解决不同问题 — 策略是"按类型路由",模板方法是"共性流程复用"。只用任何一个都不够。5 种+继续加的场景,重复代码维护成本太高。

Q: Map 做上下文不会丢类型安全吗?

ContextKey 是 enum 编译期检查,get(key, Class) 传 Class 做强转运行期检查。tradeoff 是省代码,类型安全有但不极致。

Q: 合同中心是你写的吗?

不是,是集团公共中台。我做的是业务层 — 对接它、管我们这边的状态、流程编排。

📖 问题

💡 方案:统一接口 + Spring List 自动注入

public interface ArtifactHandler {
    ContentType getType();
    void create(CreateContext ctx);
    void bindCams(BindContext ctx);
    void syncStatus(SyncContext ctx);
}

@Component
public class ScriptArtifactHandler implements ArtifactHandler {
    public ContentType getType() { return ContentType.SCRIPT; }
    // 剧本特有实现...
}

@Component
public class ArtifactHandlerFactory {
    private final Map<ContentType, ArtifactHandler> handlerMap = new HashMap<>();

    @Autowired
    public ArtifactHandlerFactory(List<ArtifactHandler> all) {
        for (ArtifactHandler h : all)
            handlerMap.put(h.getType(), h);
    }

    @PostConstruct
    public void validate() {
        // 启动时校验:同一 ContentType 只能一个 Handler
        Set<ContentType> seen = new HashSet<>();
        for (ArtifactHandler h : handlerMap.values())
            if (!seen.add(h.getType()))
                throw new IllegalStateException("重复的 ContentType");
    }

    public ArtifactHandler get(ContentType type) { ... }
}

业务代码完全不用判断类型:

handlerFactory.get(type).create(ctx);

📖 场景

💻 核心代码

public List<ArtifactScriptDO> batchCreateContentScriptForOrg(BatchCreateParam param) {
    // 步骤 1:解析 JSON 扩展字段
    List<CreateScriptWorkItem> workList = param.getWorks().stream()
            .map(this::parseExtraJson)
            .collect(toList());

    // 步骤 2:精准去重(name + cbid + workType 三维度,LinkedHashMap 保序)
    Map<String, CreateScriptWorkItem> uniqueMap = new LinkedHashMap<>();
    for (CreateScriptWorkItem w : workList) {
        String key = w.getScriptName() + "|"
                   + w.getCbid() + "|"
                   + w.getWorkType();
        uniqueMap.putIfAbsent(key, w);  // 先到先得
    }
    List<CreateScriptWorkItem> uniqList = new ArrayList<>(uniqueMap.values());

    // 步骤 3:分批调内容中心(单次上限 50 条)
    Map<Long, CreateScriptWorkItem> idMap = new HashMap<>();
    Lists.partition(uniqList, 50).forEach(batch -> {
        Map<Long, CreateScriptWorkItem> sub = batchDoCreateContentScript(batch, ...);
        idMap.putAll(sub);
    });

    // 步骤 4 & 5:反向组装 ID 映射 + 本地落库 + 幂等
    return createArtifactScripts(idMap, orgInfoDO, contractInfo);
}

🎤 面试追问

Q: 为什么用 LinkedHashMap 而不是 HashSet?

保持输入顺序(HashSet 不保证)。putIfAbsent 自然"先到先得"。

Q: 分批 50 条为啥不并行?

① 内容中心有 QPS 限制并行会被限流 ② 错误排查需要串行日志 ③ 500 条 10 批 × 200ms = 2s 可接受

Q: 中间某批失败怎么办?

部分成功策略 — 失败的入 failedList,接口返 {success, failed},运营重试失败项。不整体回滚(内容中心 delete 不一定幂等)

        // 双合同:两个都完成才是已生效
        return (isSignFinish(coop.getStatus())
                && isSignFinish(understand.getStatus()))
            ? WorkDisplayStatus.EFFECTIVE
            : WorkDisplayStatus.WAIT_SIGN;
    }
    // 单合同场景
    return isSignFinish(coop.getStatus())
            ? WorkDisplayStatus.EFFECTIVE
            : WorkDisplayStatus.WAIT_SIGN;
}

📖 问题

// 1. 分片 50 条一批
Lists.partition(all, 50).forEach(partition ->
    mapper.batchUpdateStatus(partition, newStatus));

// 2. 幂等标记
if (apply.getUpdateTaskId().equals(taskId)) continue;  // 已更新过
apply.setUpdateTaskId(taskId);

// 3. 失败重试
int retry = 0;
while (retry < 3) {
    try { doUpdate(apply); break; }
    catch (Exception e) {
        retry++;
        if (retry == 3) {
            log.error("batch update failed", e);
            Alerter.alert(...);
        } else Thread.sleep(1000);
    }
}

UPDATE org_coop_apply SET is_valid = 0

1. HashMap + computeIfAbsent 解决 N+1(必背)

Map<Long, UserDTO> cache = new HashMap<>();
list.stream().map(s -> {
    UserDTO u = cache.computeIfAbsent(
        s.getOperatorId(),
        uid -> userService.getByUserId(uid));
    vo.setOperatorName(u.getName());
    return vo;
}).collect(toList());

2. 模板方法 · 用 final 锁死流程(必背)

public abstract class Handler {
    public final Result execute(Context ctx) {
        validate(ctx);      // 基类固定
        Result r = doWork(ctx);  // 子类实现
        afterWork(r);      // 基类固定
        return r;
    }
    protected abstract Result doWork(Context ctx);
}

3. 工厂 · List 注入 + 自动装 Map(必背)

@Component
public class HandlerFactory {
    private final Map<Type, Handler> map = new HashMap<>();

    @Autowired
    public HandlerFactory(List<Handler> all) {
        for (Handler h : all) map.put(h.getType(), h);
    }

    public Handler get(Type type) {
        Handler h = map.get(type);
        if (h == null) throw new RuntimeException("unsupported");
        return h;
    }
}
