Module 01

项目定位

包名 comics-management（npm 仓库里的名字），是 Vega 后端的 Web 管理端（vega-view）。面向运营同学，做合同审核、内容管理、分销配置、数据导入等。

🎬一天的操作流

  • 运营小张登录 → Token 存 localStorage
  • 前端调 getUserInfo() → 拿到用户 + 菜单树（含权限）
  • 前端用菜单树动态生成路由（import.meta.glob 懒加载 Vue 组件）
  • 每个按钮用 v-hasPerm="['contract:create']" 指令做权限校验
  • 数据请求走封装好的 http.get/post，自动加 token、自动 loading、自动错误提示
💡
和后端 Vega 的对应关系

后端 Vega 提供 21 个 Controller 的 REST API，前端 comics-management 消费这些 API，有 46 个 apis 模块一一对应。前端的权限系统直接使用后端返回的 roles（带 ROLE_ 前缀）和 permissions（细粒度 identifier）。

Module 02 · 重点

Axios 封装 — 前后端协议真相

这是前端项目里最值得逐行讲的文件 —— utils/request.ts。包含 NProgress 自动 loading、Token 自动塞 header、code=2 登录态 SSO 跳转、code=2303 静默抛、自定义 suppressErrorMessage 等多个真实设计。

🔧真实 request.ts

TypeScriptutils/request.ts（真实完整）
import axios from "axios";
import { Message, Notification } from "@arco-design/web-vue";
import NProgress from "nprogress";
import { getToken } from "@/utils/auth";

// ⭐ NProgress 自动进度条(去掉默认 spinner 更轻量)
NProgress.configure({ showSpinner: false });

const StatusCodeMessage: Record<number, string> = {
  401: "未授权，请重新登录(401)",
  403: "拒绝访问(403)",
  500: "服务器错误(500)",
  // ... 其他状态码
};

const http: AxiosInstance = axios.create({
  baseURL: import.meta.env.VITE_API_PREFIX,
  timeout: 30 * 1000,
});

http.defaults.headers["X-Requested-With"] = "XMLHttpRequest";

// ⭐ 请求拦截器：自动 loading + 自动塞 token
http.interceptors.request.use(
  (config) => {
    NProgress.start();
    const token = getToken();
    if (token) {
      if (!config.headers) config.headers = {};
      config.headers.token = token;  // ⭐ Header 名叫 token,不是 Authorization
    }
    return config;
  },
  (error) => {
    NProgress.done();
    return Promise.reject(error);
  },
);

// ⭐⭐ 响应拦截器：按业务 code 精细分流
http.interceptors.response.use(
  (response) => {
    const { message, code, data } = response.data;
    NProgress.done();

    // ① code === 2 : 登录态失效
    if (code === 2) {
      if (import.meta.env.DEV) {
        Message.error("登录态失效");
      } else {
        // 生产环境 data 里就是 SSO 登录 URL
        window.location.href = data;
      }
      return Promise.reject(new Error("登录态失效"));
    }

    // ② code === 2303 : 特殊业务异常,调用方自己处理,不打 toast
    if (code === 2303) {
      return Promise.reject(response.data);
    }

    // ③ 其他非 0 : 根据 config 决定是否 toast
    if (code !== 0) {
      if (response.config.customParam?.suppressErrorMessage) {
        // 调用方传了 suppressErrorMessage:true → 静默
        return Promise.reject(response.data);
      } else {
        Message.error(message || "服务器端错误");
        return Promise.reject(response.data);
      }
    }

    return response.data;
  },
  (error) => {
    NProgress.done();
    Message.clear();
    const response = Object.assign({}, error.response);
    response &&
      Message.error(
        StatusCodeMessage[response.status] ||
          "系统异常, 请检查网络或联系管理员！",
      );
    return Promise.reject(error);
  },
);

// ⭐ request 再包一层: response.data.data 解出来直接返回
const request = <T = unknown>(config: AxiosRequestConfig): Promise<T> => {
  return new Promise((resolve, reject) => {
    http.request<T>(config)
      .then((res) => resolve(res.data))  // ← 再剥一层
      .catch((err) => reject(err));
  });
};

export default { request, get, post };
🎓
4 个面试必问的细节

① Header 名是 token 而不是 Authorization：历史决定，后端就这么约定的。阅文内部项目常见。
② code === 2 登录态失效：开发环境 toast，生产环境 window.location.href = data 跳转 SSO 登录 URL（data 字段返回）。
③ code === 2303 静默抛：特殊业务错误，调用方自己 try-catch 处理，不打 toast（防止干扰）。
④ suppressErrorMessage 自定义参数：调用方传 { customParam: { suppressErrorMessage: true } } 告诉 request 不要 toast。比如批量导入场景一个一个错不能每次都 toast。

💎数据结构的三层剥洋葱

后端返回的 HTTP 响应体结构是：

JSON后端响应体结构
{
  "code": 0,          // 0 = 成功,非 0 = 失败
  "message": "",       // 错误消息
  "data": {            // ⭐ 业务数据(前端真正想要的)
    "data": [...],      // 这里可能又是一层 data
    "total": 100
  }
}

前端做了两层剥离：

  1. 第一层：interceptors.response 返回 response.data（后端最外层）
  2. 第二层：request 函数 .then(res => resolve(res.data)) 再剥一层

这样业务代码拿到的已经是最里层的业务数据，无需每次 res.data.data。

C.刷新页面
D.清 localStorage
答案 B。后端在 code=2 的响应里返回 data 字段内容就是 SSO 登录 URL（带回跳参数）。前端直接跳过去，登录成功后会回跳回当前页面。这是 SSO 标准模式。

A.随便
B.特定业务错误，调用方自己捕获处理（不走通用 toast）
C.性能
D.安全
答案 B。具体 code 可能和业务约定——比如"合同已被同事签过"这种需要前端弹确认框处理的，不能粗暴 toast。后端约定 2303 为这类"预期内的业务冲突"，前端逻辑层处理。

🧩import.meta.glob 懒加载

TypeScriptstores/modules/route.ts（关键片段）
import { mapTree } from "xe-utils";
import { constantRoutes } from "@/router";

const Layout = () => import("@/layout/index.vue");

// ⭐⭐⭐ 一行代码懒加载所有 views
const modules = import.meta.glob("@/views/**/*.vue");

// 根据组件路径字符串找到对应的 import 函数
export const loadView = (view: string) => {
  let res;
  for (const path in modules) {
    // "../views/admin/list.vue" → "admin/list"
    const dir = path.split("views/")[1].split(".vue")[0];
    if (dir === view) {
      res = () => modules[path]();  // ⭐ 返回懒加载函数
    }
  }
  return res;
};

// 特殊组件名映射: "Layout" / "ParentView" / 其他按路径加载
const transformComponentView = (component: string) => {
  if (component === "Layout") return Layout as never;
  if (component === "ParentView") return ParentView as never;
  return loadView(component) as never;
};

// 把后端菜单数据转成 vue-router 的 RouteRecordRaw
const formatAsyncRoutes = (menus: MenuItem[]) => {
  if (!menus.length) return [];
  menus.sort((a, b) => (a?.sort ?? 0) - (b?.sort ?? 0));

  // ⭐ 用 xe-utils 的 mapTree 递归处理树
  const routes = mapTree(menus, (item) => {
    if (item.children?.length) {
      item.children.sort((a, b) => (a?.sort ?? 0) - (b?.sort ?? 0));
    }
    const _item = {
      path: item.path,
      name: transformPathToName(item.path),
      component: item.component ? transformComponentView(item.component) : undefined,
      redirect: item.redirect,
      meta: {
        hidden: item.hidden,
        keepAlive: item.keepAlive,
        title: item.title,
        svgIcon: item.svgIcon,
        affix: item.affix,         // ⭐ 固定标签
        showInTabs: item.showInTabs,
        activeMenu: item.activeMenu,
      },
    };
    // 清掉 undefined 字段让 route meta 干净
    Object.keys(_item.meta).forEach((key) => {
      if (_item.meta[key] === undefined) delete _item.meta[key];
    });
    return _item;
  });
  return routes as RouteRecordRaw[];
};
🎩
import.meta.glob 的魔法

这一行：
const modules = import.meta.glob('@/views/**/*.vue');

Vite 在编译时扫描 views/ 下所有 .vue 文件，生成如下对象：
{ '../views/admin/list.vue': () => import('../views/admin/list.vue'), ... }

每个 value 是 懒加载函数，调用时才真正加载代码。后端返回 "admin/list" 字符串，loadView 找到对应函数返回。
优点：① 按需加载，首屏不加载全部；② 后端改菜单配置立刻生效，无需前端发版。

动态路由
1. import.meta.glob('@/views/**/*.vue') 什么时候执行？
A.运行时，每次调用都扫描一次
B.Vite 编译时静态分析，生成含懒加载函数的对象

C.代码量更少
D.SEO 更好

Module 04 · 重点

权限体系 — v-hasPerm 指令

前端权限三件套：hasPerm() 函数 + v-hasPerm 指令 + 超管 wildcard。所有按钮级权限都走这套。

🔑has.ts 工具函数

TypeScriptutils/has.ts（真实完整）
import { useUserStore } from "@/stores";

// ⭐ 超管 wildcard 配置
const SUPER_ADMIN_PERMISSION = "*:*:*";
const SUPER_ADMIN_ROLE = "role_admin";

// 判断单个权限
export function hasPerm(permission: string): boolean {
  if (!permission) return false;
  const permissions = useUserStore().permissions;
  // ⭐ 命中超管 wildcard 或者具体权限 identifier
  return permissions.some((v) => v === SUPER_ADMIN_PERMISSION || v === permission);
}

// 任一权限命中即可
export function hasPermOr(permissions: string[]): boolean {
  return permissions.some(hasPerm);
}

// 全部权限都命中
export function hasPermAnd(permissions: string[]): boolean {
  return permissions.every(hasPerm);
}

export function hasRole(role: string): boolean {
  if (!role) return false;
  const roles = useUserStore().roles;
  return roles.some((v) => v === SUPER_ADMIN_ROLE || v === role);
}

🎨v-hasPerm 自定义指令

TypeScriptdirectives/hasPerm.ts（真实）
import { hasPermOr } from "@/utils/has";

function checkPermission(el: HTMLElement, binding: DirectiveBinding<string[]>) {
  const { value } = binding;

  if (!value || !Array.isArray(value) || value.length === 0) {
    throw new Error(
      '权限参数格式错误，示例：v-hasPerm="[\'home:btn:edit\',\'home:btn:delete\']"'
    );
  }

  const hasPermission = hasPermOr(value);

  if (!hasPermission) {
    // ⭐ 直接从 DOM 移除元素(不是 display:none 或 v-if)
    el.parentNode?.removeChild(el);
  }
}

const hasPermDirective: Directive = {
  mounted(el, binding) { checkPermission(el, binding); },
  updated(el, binding) { checkPermission(el, binding); },
};

⚠️
removeChild vs v-if 的取舍

代码里用 el.parentNode?.removeChild(el) 直接从 DOM 砍掉元素，而不是 display: none。对比：
• removeChild：元素彻底消失，F12 看不到、JS 获取不到、事件/watcher 不存在。安全性好（无权限用户理论上 DOM 都看不见按钮）。
• v-if：效果类似但 Vue 管理生命周期，性能稍好。
• display:none：F12 能看到，技术好的用户能改样式显示出来再点击——安全性差。

但：前端权限校验只是"UI 层的便利"，真正的权限必须后端校验！前端砍了按钮不代表安全。

👑超管 wildcard 设计

权限字符串含义匹配
*:*:*全量权限任意 hasPerm() 都返回 true
role_admin超管角色任意 hasRole() 都返回 true
contract:create具体权限精确匹配
home:btn:edit三段式权限模块:对象:操作
💎
权限命名约定

看源码 home:btn:edit 这种格式，和后端对应的是 PermissionDO.identifier 字段。命名约定：模块:对象:操作，比如：
• contract:btn:create — 合同模块的创建按钮
• settlement:list:view — 结算列表的查看权限
• admin:user:disable — 管理员的用户禁用操作

规范命名的好处是运营配置权限时一眼懂。

🧪 检验理解 · Module 4
权限指令
1. v-hasPerm 为啥用 removeChild 而不是 display:none？
A.性能
B.更彻底——F12 看不到、JS 获取不到，防止被手动改样式绕过
C.Vue 限制
D.美观
答案 B。display:none 攻击者能用 F12 改样式显示出来再点击（虽然后端还会拦，但不够干净）。removeChild 让元素彻底从 DOM 消失，没了就是没了。
2. hasPermAnd(['a', 'b']) 和 hasPermOr(['a', 'b']) 的区别？
A.一样
B.And 必须同时有 a 和 b；Or 任一有即可（v-hasPerm 指令用的是 Or）
C.And 是与门，Or 是或门
D.命名混淆
答案 B。hasPermAnd 用 .every()（全部命中），hasPermOr 用 .some()（任一命中）。指令默认 Or——写 v-hasPerm="['edit', 'admin']" 意思是"有编辑或管理员权限就显示"。
3. 前端权限校验能替代后端校验吗？
A.能，后端不用校验
B.不能，前端只是 UI 便利，真正的安全必须后端接口层校验
C.能，HTTPS 已足够
D.不知道
答案 B。前端代码对攻击者完全可见，F12 / Postman 可以绕过。前端权限只是"让没权限的用户看不到按钮"，真正的权限必须在后端 Controller 层（Spring Security @PreAuthorize）再次校验。"前后端双层权限"是标准做法。
Module 05

Pinia 状态架构

5 个 store modules：app / dict / route / tabs / user。全部使用 Setup Store（组合式，ref+computed 而非 options），职责清晰。

🧠User Store 真实代码

TypeScriptstores/modules/user.ts（真实）
import { defineStore } from "pinia";
import { computed, reactive, ref } from "vue";
import { getUserInfo } from "@/apis/user";

// ⭐ Setup Store 写法(推荐),用 setup 函数而非 options 对象
const storeSetup = () => {
  const userInfo = reactive({
    userName: "", email: "", avatar: "",
  });

  const name = computed(() => userInfo.userName);
  const avatar = computed(() => userInfo.avatar);

  const roles = ref<string[]>([]);           // 角色列表
  const permissions = ref<string[]>([]);     // 权限列表

  // 特殊能力:评级是否可见(从权限计算)
  const ratingVisible = computed(() =>
    permissions.value.includes("show:drama-rating")
  );

  // ⭐⭐ 用户初始化:拉取 user + menu + 绑定埋点
  const getInit = async () => {
    try {
      const res = await getUserInfo();
      const { user, menu } = res;

      userInfo.userName = user.userName;
      userInfo.email = user.email;

      // ⭐ 绑定腾讯 Aegis 埋点 uid
      if (window.AegisV2) {
        window.AegisV2.setConfig({
          uid: `${user?.userName}_${user?.userId}`,
        });
      }

      // 取角色 tag
      roles.value = user.roles.map((role) => role.tag);

      // ⭐ 递归菜单,收集所有 permission identifier,同时过滤隐藏菜单
      function filterMenu(menu: any[]) {
        return menu.filter((item) => {
          permissions.value.push(item.authority.identifier);
          if (item.children?.length > 0) {
            item.children = filterMenu(item.children);
          }
          // type === 3 可能是按钮级权限(不要作为菜单显示)
          return item.authority.type !== 3;
        });
      }

      return filterMenu(menu);
    } catch (error) {
      console.error("获取用户信息失败:", error);
      throw error;
    }
  };

  return { userInfo, name, avatar, email, roles, permissions, ratingVisible, getInit };
};

// ⭐ persist: false → 不持久化到 localStorage(防止 token 失效后还能看到旧数据)
export const useUserStore = defineStore("user", storeSetup, { persist: false });
💎
4 个设计细节

① Setup Store 写法：用 () => { ... return {...} } setup 函数，而不是 { state, getters, actions } options。现代 Pinia 推荐，读起来像写 composable。
② permissions 从 menu 递归收集：不单独拉 permission 列表，减少接口。
③ type !== 3 过滤：权限 authority 有 type 字段区分菜单/页面/按钮（按钮不作为侧栏菜单显示）。
④ persist: false：不持久化。如果 token 过期了，刷新页面会强制重新拉 user + menu，保证菜单/权限实时性。

📋5 个 Store 各司其职

Store职责持久化
user用户信息、角色、权限、菜单❌（每次登录重拉）
app主题、侧栏折叠、语言设置✅ localStorage
dict字典缓存（状态枚举、分类等）按需缓存
route动态路由 + 常量路由❌（每次重新 addRoute）
tabs多标签页 + keep-alive 缓存列表❌
🧪 检验理解 · Module 5
Pinia 状态
1. Setup Store 比 Options Store 好在哪？
A.性能更好
B.语法和 Vue 3 Composition API 一致，可以内部调用 composable、更好的 TypeScript 推导
C.Pinia 只支持它
D.一样
答案 B。Setup Store 就是一个 setup 函数，里面可以 useRouter()、ref()、watch()，和写组件一样。Options Store 受对象结构限制，不能嵌套使用其他 composable。
2. user store 为啥 persist: false？
A.用不上
B.token 过期后刷新页面要强制重拉 user + menu，保证权限实时
C.性能
D.隐私
答案 B。如果持久化用户信息到 localStorage，刷新时直接用本地的，token 失效了也不知道。不持久化 → 刷新时触发 getUserInfo → 如果 token 失效走 code=2 → 跳转 SSO。保证安全。
Module 06

Tabs 多标签系统

B 端后台标配——已打开页面做成标签页，可以快速切换、固定、关闭、配合 <keep-alive> 缓存。

🗂️Tabs Store 核心

TypeScriptstores/modules/tabs.ts（关键方法）
const storeSetup = () => {
  const router = useRouter();

  // 当前打开的标签列表
  const tabList = ref<RouteLocationNormalized[]>([]);

  // ⭐ keep-alive 的 include 列表(用路由 name 做 key)
  const cacheList = ref<RouteRecordName[]>([]);

  // 添加标签
  const addTabItem = (item: RouteLocationNormalized) => {
    const index = tabList.value.findIndex((i) => i.path === item.path);

    if (index >= 0) {
      // 已存在但 query 不同 → 更新
      if (tabList.value[index].fullPath !== item.fullPath) {
        tabList.value[index] = item;
      }
    } else {
      // 不存在 → 添加(除非 meta.showInTabs === false)
      if (item.meta?.showInTabs ?? true) {
        tabList.value.push(item);
      }
    }
  };

  // 删除标签
  const deleteTabItem = (path: string) => {
    // ⭐ affix(固定)标签不能删
    const index = tabList.value.findIndex(
      (item) => item.path === path && !item.meta?.affix
    );
    if (index < 0) return;

    const isActive = router.currentRoute.value.path === tabList.value[index].path;
    tabList.value.splice(index, 1);

    // ⭐ 删的是当前激活页 → 跳到最后一个标签
    if (isActive && tabList.value.length) {
      const lastTab = tabList.value[tabList.value.length - 1];
      router.push(lastTab.fullPath || lastTab.path);
    }
  };

  // 清空(除 affix)
  const clearTabList = () => {
    const routeStore = useRouteStore();
    const affixTabs = [];
    // ⭐ xe-utils 的 eachTree 遍历路由找 affix:true
    eachTree(routeStore.routes, (item) => {
      if (item.meta?.affix) affixTabs.push(item);
    });
    tabList.value = affixTabs;
  };

  // ⭐ Keep-alive 缓存管理
  const addCacheItem = (item) => {
    if (!item.name || !item.meta?.keepAlive) return;
    if (!cacheList.value.includes(item.name)) {
      cacheList.value.push(item.name);
    }
  };

  // 关闭当前标签时同时清缓存
  const closeCurrent = (path: string) => {
    const item = tabList.value.find((i) => i.path === path);
    if (item?.name) deleteCacheItem(item.name);
  };
};
🎯
Tabs 系统的 3 个关键 meta 字段

路由 meta 定义了 Tabs 行为：
• showInTabs（默认 true）：是否作为标签显示（比如登录页设 false）
• affix：固定标签，不能删除（首页常这么设）
• keepAlive：切换时缓存组件状态（表格筛选条件、滚动位置）

业务代码只要在 router meta 里配好这 3 个字段，Tabs 和 keep-alive 自动生效。

🔗和 <keep-alive> 的联动

Vuelayout/index.vue 里的 keep-alive（示意）
<router-view v-slot="{ Component, route }">
  <keep-alive :include="tabsStore.cacheList">
    <component :is="Component" :key="route.fullPath" />
  </keep-alive>
</router-view>

:include 绑定到 Pinia 里的 cacheList——响应式。addCacheItem 往里 push name，对应组件被 keep-alive 缓存；deleteCacheItem 删除后组件被销毁。

🧪 检验理解 · Module 6
Tabs 系统
1. 想让一个页面"关闭后再次打开时，表格筛选条件保留"，该怎么做？
A.写进 localStorage
B.路由 meta 加 keepAlive: true，自动走 keep-alive 缓存
C.URL 带参数
D.做不到
答案 B。keep-alive 是 Vue 组件级缓存。配合 Tabs 的 cacheList，只要 meta.keepAlive=true 就会被缓存。用户切回来时组件没被销毁，所有 state 保留（但和 localStorage 不同，关闭浏览器就没了）。
2. closeCurrent 关闭标签时为啥同时清 cacheList？
A.美观
B.用户明确关闭的意图 = 不想保留，清缓存释放内存并确保下次打开是全新状态
C.性能
D.规范
答案 B。"关闭标签"的语义 = 我不要这个页面了。缓存保留会让"再次打开时还是旧状态"，多半不符合用户期待（我想要个新的表单）。同时清 cacheList 语义清晰。

Vite 构建优化

线上应用性能的关键——vite.config.ts 里有不少优化细节。

⚙️真实 vite.config.ts

TypeScriptvite.config.ts（真实关键配置）
export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd());
  return {
    // ⭐ base 支持 CDN 部署
    base: process.env.cdnUrl || env.VITE_BASE,

    resolve: {
      alias: {
        "~": fileURLToPath(new URL("./", import.meta.url)),
        "@": fileURLToPath(new URL("./src", import.meta.url)),
      },
    },

    server: {
      port: 9999,
      proxy: {
        // ⭐ 开发环境 /api 代理到后端
        "/api": {
          target: env.VITE_API_BASE_URL,
          changeOrigin: true,
        },
      },
    },

    plugins: [
      vue(),
      vueJsx(),

      // ⭐ 自动 import Vue/Vue Router API 和 Arco 组件
      AutoImport({
        imports: ["vue", "vue-router", {
          vue: ["useTemplateRef", "onWatcherCleanup", "useId"]
        }],
        dts: "src/auto-import.d.ts",
        resolvers: [ArcoResolver()],
      }),

      // ⭐ 自动注册 components 目录下的组件
      Components({
        dirs: ["src/components"],
        dts: "src/components.d.ts",
        resolvers: [
          ArcoResolver({
            sideEffect: true,       // 样式按需自动导入
            resolveIcons: true,     // Arco 图标按需
          }),
        ],
      }),

      // ⭐ SVG 图标精灵方案
      createSvgIconsPlugin({
        iconDirs: [path.resolve(process.cwd(), "src/icons")],
        symbolId: "icon-[dir]-[name]",
      }),

      // ⭐ Mock Server(开发 + 生产 injectCode)
      viteMockServe({
        mockPath: "mock",
        localEnabled: true,
        prodEnabled: false,
      }),
    ],

    build: {
      chunkSizeWarningLimit: 2000,   // 单 chunk 警告阈值
      outDir: "dist",

      minify: "terser",
      terserOptions: {
        compress: {
          drop_console: true,      // ⭐ 生产环境去掉 console
          drop_debugger: true,
        },
        format: { comments: false },  // 去除所有注释
      },

      rollupOptions: {
        output: {
          // 静态资源分目录输出
          chunkFileNames: "static/js/[name]-[hash].js",
          entryFileNames: "static/js/[name]-[hash].js",
          assetFileNames: "static/[ext]/[name]-[hash].[ext]",

          // ⭐⭐⭐ 手动分包:大依赖独立 chunk,提升缓存命中
          manualChunks(id) {
            if (id.includes("node_modules")) {
              if (id.includes("vue")) return "vue";
              if (id.includes("echarts")) return "echarts";
              if (id.includes("vtable")) return "vtable";
              return "vendor";
            }
          },
        },
      },
    },
  };
});
🎓
5 个面试追问的优化点

① AutoImport + Components：写代码时不用手动 import { ref, computed } from 'vue'，插件自动处理。Arco 组件按需引入，不打包完整 UI 库。
② manualChunks 分包策略：vue / echarts / vtable / vendor 分成独立 chunk。好处：更新业务代码不影响这些大依赖的 hash，浏览器缓存继续有效。
③ terser drop_console：生产包去 console，减少体积+避免信息泄露。
④ SVG 图标精灵：src/icons 下的 SVG 打包成精灵图，symbolId: "icon-[dir]-[name]"。
⑤ vite-plugin-mock：开发时本地 mock 数据，开后端接口没好的情况下前端照样开发。

🧪 检验理解 · Module 7
构建优化
1. manualChunks 按 "vue/echarts/vtable/vendor" 分包，好处是什么？
A.性能更好
B.业务代码更新时，这些大依赖 chunk 的 hash 不变，浏览器缓存继续用
C.打包更快
D.CDN 要求
答案 B。如果所有 node_modules 打一个大 vendor chunk，任何业务更新都会让整个 vendor hash 变，用户重新下载 MB 级的依赖。分包后：echarts 几乎不升级 → 永久缓存。业务改 → 只重下业务 chunk。关键的首屏加速手段。
2. AutoImport 插件干什么？
A.自动安装 npm 包
B.代码里用 ref() / computed() 不用手写 import，插件编译时自动加上
C.自动引入 CSS
D.无用
答案 B。减少样板代码——Composition API 用得多时，一个文件可能 import 十几个 Vue API。插件自动扫描你用了哪些，编译时添加 import 语句。搭配 dts: 'src/auto-import.d.ts' 生成类型声明文件让 TS 能识别。
3. Vite 开发时 proxy: '/api' 的作用？
A.HTTPS
B.前端 localhost:9999 的 /api 请求会被代理到后端服务，绕过 CORS
C.加速
D.隐藏密钥
答案 B。开发时前端跑在 localhost:9999，后端跑在另一个域名。浏览器直连后端有 CORS 问题，但前端只调 /api/...，Vite dev server 代理到后端。生产环境由 Nginx 同样路径做代理。
